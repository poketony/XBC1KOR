# Xenoblade Wii 한글화 에디터

2026-09-23 개발판. 「저장·게임에 반영」은 원본을 백업한 뒤 게임 파일과 static.arc_OUT을 갱신한다. 「수정본 내보내기」는 새 폴더에 출력한다. 실기 및 에뮬레이터에서 적용 검증한 정식판은 아니다.

화면은 제공받은 Wii 커버 아트와 모나드 아이콘을 사용한다. `wii_editor_assets` 폴더를 실행 파일과 함께 유지한다. 일본어 문자열은 Meiryo → Yu Gothic → MS Gothic 순으로 설치된 글꼴을 사용하여 장음 부호 `ー`를 표시한다. 원본 CP932 데이터는 표시 문제를 해결하기 위해 치환하지 않는다.

## 실행과 작업

1. `Wii 에디터 실행.pyw`를 Python으로 실행한다. 현재 작업 PC에는 Python, Tkinter, Pillow가 설치되어 있다. `.pyw` 연결이 없으면 `Wii 에디터 실행.cmd`를 사용한다.
2. **게임 루트 열기**에서 Wii의 `files` 폴더를 선택한다. 상위 `XenoEX` 폴더도 인식한다. 정상적으로 연 `files` 경로는 에디터 옆 `wii_editor_settings.json`에 저장되어 다음 실행 때 자동으로 열린다. 다른 루트를 정상적으로 열기 전까지 유지하며, 디스크가 빠져 있어도 기억한 경로를 지우지 않는다. 작업 중인 미저장 수정 내용과 별도 지정한 static 폴더는 이 설정에 저장하지 않는다.
3. 게임 루트의 `static.arc_OUT`을 기본으로 자동 감지하며, 그 안의 PKH와 내부 파일을 우선 읽는다. 다른 위치는 **static 폴더 지정**으로 선택한다. 해당 자료가 없으면 기존 static 폴더와 원본 `static.arc`도 보조적으로 읽는다.
4. 왼쪽에서 영역, 패키지 항목을 펼친 뒤 내부 파일을 선택한다. 실제 내부 이름과 BDAT 식별자가 있으면 표시한다. 해시만 남은 외부 이름은 복원했다고 주장하지 않는다.
5. **문자열 / 자막**에서 행을 선택하고 수정한 뒤 **문장 반영**을 누른다. 다른 행·파일로 이동하거나 저장할 때도 입력한 문장을 반영한다.
   BRLYT 행은 **텍스트 상자 속성**에서 상자·글자 크기, 간격, UTF-16 버퍼 용량을 수정할 수 있다. 일반 문장 편집은 기존 버퍼 용량을 줄이지 않는다. 줄이려면 속성 창에서 명시적으로 용량을 지정한다.
6. **이미지**에서 미리보기, PNG 내보내기, PNG 교체 (TPL은 크기 변경 가능)를 사용할 수 있다.
7. **저장·게임에 반영**을 누르면 게임 루트 옆 `editor_backups/날짜_고유번호`에 원본을 먼저 백업한 뒤, 변경 파일과 재포장한 `static.arc`, 기존 `static.arc_OUT`의 대응 파일을 함께 갱신한다. 저장 실패 시 교체한 파일은 백업에서 복원한다.
8. 다른 곳에 따로 저장하려면 **수정본 내보내기**에서 새 폴더를 지정한다. 변경된 PKB, PKH, REV, static 내부 파일과 재포장된 `static.arc`가 출력된다. 출력은 게임 전체가 아닌 변경분이다.
9. **문자 매핑 불러오기**는 UTF-16 `.tbl`과 기존 JSON을 지원한다. 선택한 테이블은 게임 루트별로 기억하며 목록·검색·편집창은 한글로 표시하고 저장할 때 게임 코드로 변환한다. BRLYT의 Unicode 텍스트에는 이 치환을 적용하지 않는다. 테이블에 없는 한글은 저장 오류로 알리며 임의로 바꾸지 않는다.

일반 작업은 **저장·게임에 반영** 버튼만 사용하면 된다. 기본 `static.arc_OUT`을 사용하는 작업본에서 직접 반영을 지원한다. 실제 게임 실행 및 레이아웃 결과는 별도로 확인해야 한다.

## 편집 범위

- PKB/PKH 항목, U8, BDAT 묶음, ARC, DAP 중첩 구조를 탐색하고 수정한 내부 파일을 역순으로 포장한다.
- ADX·AHX의 PKB는 AFS 아카이브다. PKH에 별도 위치 표가 없는 경우 AFS 본문의 위치·길이 표로 목록을 읽는다. 오디오 재생·편집은 지원하지 않는다.
- Wii SB, BDAT 문자열, BRLYT 텍스트, REV 자막을 편집한다.
- 루트 단독 파일과 `hbm.arc_OUT` 내부도 탐색·편집·새 출력 저장이 가능하다. 지원하지 않는 내부 포맷은 편집 가능한 것으로 표시하지 않는다.
- Wii RFNA(BRFNA) 시트를 PNG로 교체하고 Huffman8·GLGR·참조 주소를 재구성한다. **폰트 문자표 / 폭**에서 기존 문자 코드와 글리프 폭을 편집한다. 시트 수·격자 확대, 일반 BRFNT, `01 ARC` 래퍼는 이 기능의 지원 범위가 아니다.
- TPL 및 지원되는 BRRES/REV 텍스처를 미리보기·교체한다. 모델·효과 등의 불투명 데이터는 해석하여 편집하지 않는다.
- 한글 → 게임 문자 JSON 매핑을 불러올 수 있다. 이는 문자 치환 기능이며 한글 폰트를 자동으로 만드는 기능이 아니다. 매핑이 없으면 CP932로 표현할 수 없는 한글 저장은 실패한다.

## 원래 공간을 넘는 수정

SB·BDAT는 사용 중인 모든 문자열로 풀을 재구성한다. BRLYT는 수정한 txt1 버퍼를 교체하고 섹션 크기를 갱신한다. U8·ARC·DAP·BDAT 묶음은 모든 구성원을 재배치하고, PKB는 전체 항목을 스트리밍으로 다시 배치하며 PKH를 갱신한다. REV는 메타데이터 뒤에 자막을 다시 만들고 복호화 범위·읽기 범위·리소스 주소를 갱신한다. 이전 수정문을 뒤에 누적하지 않으며, 짧게 수정하면 재사용하지 않는 공간을 회수한다. 무수정 입력은 원본 바이트를 반환한다.

다만 BDAT의 문자열 시작 주소는 Wii 실행파일이 실제로 16비트로 읽는다. 이 주소 범위를 넘는 수정은 명확한 오류로 거부한다. BRLYT 필드 길이 등 실제 포맷 한계도 유지한다. 원래 문자열 길이 제한 해제와 실행파일의 주소 표현 범위 변경은 서로 다른 작업이다.

메모리 보호를 위해 선택 항목 읽기는 64 MiB, 수정 캐시는 128 MiB로 제한한다. 저장 후에도 작업 사본은 유지되므로 캐시가 가득 차면 저장된 변경분을 작업용 게임 복사본에 반영한 뒤 다시 연다. 원본 게임에는 직접 반영하지 않는다.

## 이미지 변환

Wii 메뉴에서 확인한 I4, I8, IA4, IA8, RGB565, RGB5A3, C4, C8, CMPR와 RGBA8 코드를 지원한다. 변경하지 않은 이미지는 원본 바이트를 그대로 반환한다.

팔레트 이미지는 원본 팔레트를 유지한다. 원본에 없는 색을 넣으려면 **손실 변환 허용**을 선택해야 하며 가장 가까운 팔레트 색으로 변환한다. CMPR 재압축도 이 선택이 필요하다. 저비트 색상 형식은 표현 가능한 색상 정밀도로 반올림된다. 독립 TPL과 REV RED 내부 TPL은 이미지 크기 변경 시 헤더·픽셀 버퍼·팔레트 위치를 재구성한다. REV에서는 RED 크기·후속 리소스 주소도 갱신한다. TPL의 기존 mip 단계가 있으면 변경한 이미지에서 최근접 보간으로 다시 만든다. **C4/C8 TPL 팔레트 새로 생성**과 **손실 변환 허용**을 함께 선택하면 새 PNG에서 팔레트를 생성한다. C4는 최대 16색, C8은 최대 256색으로 양자화하며 RGB5A3 팔레트로 저장한다. 다른 이미지의 팔레트·픽셀은 보존한다. BRRES 텍스처 크기 변경은 아직 지원하지 않는다.

## 검증과 남은 사항

`python -m unittest discover -s codex-lab -p 'test_wii*.py' -v`

30개 회귀 검사 중 기존 에디터 검사: SB 장문·포인터 확장, BDAT→PKB/PKH 저장·재읽기 및 다른 항목 보존, 중첩 메뉴 이미지 교체, 실제 메뉴의 9종 형식 무수정 왕복, 팔레트·니블 픽셀 수정, REV 1만 바이트 자막과 리소스 보존, Tk 창과 GUI 문장 반영. 루트 설정 검사는 재시작 복원, 디스크 분리 시 설정 보존, 취소·잘못된 선택 시 기존 설정 유지, 손상된 설정 파일 처리를 다룬다.

추가 리빌드 검사는 반복 수정 후 축소, 중첩 아카이브 보존, TPL 및 REV 이미지 크기 변경을 다룬다. 실제 파일 범위 검사에서는 텍스트가 있는 BDAT 143개, SB 1,156개, BRLYT 77개, REV 138개가 증가·감소·재읽기를 통과했다. 결과는 WII_REBUILD_CORPUS_RESULT.json에 기록했다. 모든 편집 조합이나 게임 실행을 검증한 것은 아니다. 저장은 먼저 `.incomplete-고유번호` 임시 폴더에 쓰고 검증한 다음 최종 출력 이름으로 바꾼다. 실패한 임시 폴더는 사용하지 않는다. 실패 시 수정 캐시와 미저장 상태를 유지한다. 실기 적용, 한글 폰트 배치, 전 영역 완전 지원, BRRES 이미지 크기 변경은 완료 범위에 포함하지 않는다. 이 변경은 현재 Wii 에디터 경로에 적용한 것으로, 과거 배포 묶음이나 3DS 전용 relocate.py의 구현까지 교체한 것은 아니다.

## 전체 텍스트 JSON 추출 (CLI 전용)

```powershell
python codex-lab/wii_text_export.py "E:/Xenoblade/Xenoblade Wii/files" "codex-lab/my-wii-text"
```

출력은 새 폴더여야 한다. 영역을 제한하려면 `--areas common map menu script static ev loose` 중 필요한 이름만 지정한다. 별도 static 폴더는 `--static 경로`로 지정한다. GUI 버튼은 추가하지 않았다.

영역별 JSON에는 원본 파일·PKB 항목·중첩 컨테이너 경로·파일 해시·원본 행 식별자·바이트·제어문자·번역용 빈 필드가 들어간다. 문자열이 같아도 합치지 않는다. 파일 단위로 순차 읽기·기록하며 게임 전체를 메모리에 올리지 않는다. JSON 자체를 자동 재삽입하는 importer나 Switch 번역 매칭 DB는 이번 기능에 포함하지 않는다.

`WII_TEXT_EXPORT.md`에 스키마와 실제 추출 결과·누락 판정 기준을 기록했다.
